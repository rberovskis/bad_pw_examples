Playwright SDET Interview

L3 — Senior Rules

L3 — Senior 15 rules 2 bad + 2 good examples per rule Talking points included

Async Correctness

missing-playwright-await Unawaited Playwright assertions return a Promise that is silently discarded — the test always passes regardless of page state no-test-return-statement Playwright ignores a test callback's return value, so return somePromise neither awaits it nor propagates its rejection valid-expect-in-promise Assertions inside .then() chains that are not returned or awaited are detached from the test runner and never fail the test

Timeout Management

no-action-timeout Per-action timeout overrides fragment the timeout budget across the suite; timeout: 0 removes the circuit breaker entirely require-to-pass-timeout toPass() defaults to timeout: 0 (unbounded retry), silently hanging the suite when the condition is never met

Network Timing

no-networkidle networkidle relies on a 500 ms / 0-request heuristic that breaks on polling, WebSockets, and analytics beacons no-wait-for-navigation waitForNavigation is event-based and race-prone; registering the listener after the triggering action misses navigations on fast machines

Locator Strategy & Retry Logic

no-wait-for-selector waitForSelector returns a stale ElementHandle — any DOM re-render between acquisition and use causes a detached-element error

Flakiness & Hard-coded Delays

no-wait-for-timeout Hard-coded waitForTimeout sleeps are browser-state-unaware — they either under-wait on slow CI or over-wait always

Assertion Correctness

no-conditional-expect Assertions inside if/catch/ternary blocks may be skipped entirely — a test with zero executed assertions still passes prefer-ending-with-an-expect A test ending on an action proves actionability, not correctness — the resulting state is never verified prefer-web-first-assertions Instance methods like .isVisible() take a point-in-time snapshot with no retry; web-first assertions poll until the assertion passes or times out

Assertion Strategy

require-soft-assertions Hard expect() halts the test on first failure, hiding all subsequent assertion results; expect.soft() accumulates all failures before reporting

Browser/Node Context Boundary

no-unsafe-references Closures in page.evaluate / addInitScript are serialized and re-evaluated in the browser — outer-scope variables resolve to undefined silently
