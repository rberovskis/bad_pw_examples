missing-playwright-await

L3 — Senior Async Correctness False Positives Promise Lifecycle

Why this rule exists

Playwright's assertion and navigation APIs return Promises that must be awaited for the engine to perform its internal retry logic, DOM polling, and network synchronization. When a call like expect(locator).toBeVisible() is not awaited, the test runner discards the Promise and moves on immediately — the assertion never actually executes, so the test passes regardless of the page state. For waitForResponse and similar methods, skipping await means the event listener is registered after the triggering action, creating a race condition that silently succeeds on fast machines but flakes in CI.

What interviewers look for

  • The candidate explains that un-awaited Playwright matchers silently no-op: the test appears green but no assertion was made, producing a false positive that masks real regressions.
  • The candidate understands the difference between registering a Promise (setting up the listener) and awaiting it (blocking until resolution), and why order matters especially for network interception with waitForResponse / waitForRequest.
  • The candidate can describe the correct patterns: direct await, destructured Promise.all for concurrent listen-then-act, and await test.step(...) for named step grouping.

Examples

Bad — Unawaited assertion silently passes on broken UI BAD 1 
import { test, expect } from '@playwright/test';

test('user can submit the login form and reach the dashboard', async ({ page }) => {
  await page.goto('/login');

  await page.getByLabel('Email').fill('user@example.com');
  await page.getByLabel('Password').fill('hunter2');
  await page.getByRole('button', { name: 'Sign in' }).click();

  // BUG: no await — this assertion is never evaluated.
  // The test passes even if the redirect never happens.
  expect(page.getByRole('heading', { name: 'Dashboard' })).toBeVisible();
  expect(page.getByText('Welcome back, user@example.com')).toBeVisible();
});
What's wrong: Both expect(...).toBeVisible() calls return Promises that are never awaited. Playwright's internal retry loop never runs — the assertions are discarded and the test always reports green regardless of what is rendered after login.
Bad — Race condition from registering a network listener too late BAD 2 
import { test, expect } from '@playwright/test';

test('checkout flow posts order and shows confirmation number', async ({ page }) => {
  await page.goto('/checkout');

  await page.getByLabel('Card number').fill('4111111111111111');
  await page.getByLabel('Expiry').fill('12/29');
  await page.getByLabel('CVV').fill('123');

  await page.getByRole('button', { name: 'Place order' }).click();
  page.waitForResponse('/api/orders'); // no await + registered AFTER click

  await expect(page.getByTestId('confirmation-number')).toBeVisible();
});
What's wrong: waitForResponse is not awaited, so the result Promise is abandoned and the test never waits for the response. The listener is also registered after the triggering click — introducing a race even if await were added.
Good — All assertions properly awaited GOOD 1 
import { test, expect } from '@playwright/test';

test('user can submit the login form and reach the dashboard', async ({ page }) => {
  await page.goto('/login');

  await page.getByLabel('Email').fill('user@example.com');
  await page.getByLabel('Password').fill('hunter2');
  await page.getByRole('button', { name: 'Sign in' }).click();

  await expect(page.getByRole('heading', { name: 'Dashboard' })).toBeVisible();
  await expect(page.getByText('Welcome back, user@example.com')).toBeVisible();
});
Why this works: Each await transfers control to Playwright's assertion engine, which retries the DOM check with built-in timeouts. The test only proceeds — or fails — once each condition is definitively resolved.
Good — Network listener registered before the triggering action via Promise.all GOOD 2 
import { test, expect } from '@playwright/test';

test('checkout flow posts order and shows confirmation number', async ({ page }) => {
  await page.goto('/checkout');

  await page.getByLabel('Card number').fill('4111111111111111');
  await page.getByLabel('Expiry').fill('12/29');
  await page.getByLabel('CVV').fill('123');

  const [orderResponse] = await Promise.all([
    page.waitForResponse((resp) => resp.url().includes('/api/orders') && resp.status() === 201),
    page.getByRole('button', { name: 'Place order' }).click(),
  ]);

  const { orderId } = await orderResponse.json();
  await expect(page.getByTestId('confirmation-number')).toHaveText(orderId);
});
Why this works: The waitForResponse listener is in place before click() fires, eliminating the race. Promise.all keeps both concurrent — the response resolves as soon as it arrives, and await ensures the test blocks until both Promises settle.

Interview talking points

Gotcha question

"If an un-awaited expect(...).toBeVisible() doesn't throw, how would you ever know your test was silently skipping the assertion in a real CI pipeline?"

Expected senior answer

The only reliable indicator is a failing test when the UI is intentionally broken — a test that always passes regardless of DOM state is a false positive. They would enforce the ESLint rule in CI so the linter catches it before the test runner is even invoked. Playwright's --reporter=html won't surface un-awaited assertions as failures — static analysis is the only safety net.

Common misconception

Junior/mid candidates often believe that because the test file uses async/await elsewhere, any Playwright call inside an async function is automatically awaited. They conflate "the function is async" with "every expression inside it is awaited," not realizing that a Promise returned from an un-awaited call is simply garbage-collected without execution.
